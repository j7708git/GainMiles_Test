## 4. 資料庫 schema 契約

主檔 id 用 `INTEGER GENERATED BY DEFAULT AS IDENTITY`；所有下述業務欄位 NOT NULL。

題目沒有指定 PK。以下是預設方案，不宣稱為考官唯一要求；不設商品 id、改 code 當主鍵的建表／外鍵／API 差異見獨立備案。預設備案不得在同一資料庫混合執行。

| 表 | 欄位與約束 |
| --- | --- |
| products | id PK；name VARCHAR(128) 非空白；code VARCHAR(32) UNIQUE 非空白；category_id INTEGER FK categories.id RESTRICT；unit_price NUMERIC(10,2) CHECK 0 ≤ price ≤ 99999999.99；inventory INTEGER CHECK inventory ≥ 0 |
| categories | id PK；name VARCHAR(64) UNIQUE 非空白 |
| sizes | id PK；code VARCHAR(32) UNIQUE 非空白 |
| colors | id PK；name VARCHAR(64) UNIQUE 非空白 |
| product_sizes | product_id FK products.id ON DELETE CASCADE；size_id FK sizes.id ON DELETE RESTRICT；複合 PK(product_id,size_id) |
| product_colors | product_id FK products.id ON DELETE CASCADE；color_id FK colors.id ON DELETE RESTRICT；複合 PK(product_id,color_id) |

非空白以 `length(btrim(column)) > 0` 類型 CHECK 表達；API 先 trim 首尾空白。庫存 API 上限 2147483647（INTEGER 最大值）。屬性大小寫敏感，`Red` 與 `red` 不自動視為同名，文件需寫清楚。

每商品至少一尺寸一顏色，由 API 層交易驗證；一般外鍵不能保證父商品一定有子列，**不宣稱 DB 單獨能保證這點**。不加複雜 trigger。

刪商品只連帶刪映射；共用 category/size/color 保留，不連帶刪掉其他商品。API 不提供直接刪共用屬性的端點。

新屬性由商品寫入時取得或建立，名稱唯一、同一交易完成；處理併發插入同名屬性可用 PostgreSQL `ON CONFLICT DO NOTHING` 後查 id，不把正常的共用屬性競爭誤回商品 code 衝突。

## 5. JSON 欄位契約

| 題目欄位 | JSON 欄位 | 類型與規則 |
| --- | --- | --- |
| Name | name | 字串，trim 後 1–128 字 |
| code | code | 字串，trim 後 1–32 字；唯一、大小寫敏感；不硬限制 A-001 格式 |
| category | category | 字串，trim 後 1–64 字 |
| size | sizes | 輸入字串陣列或分隔字串；正規化後 1–50 項，每項 trim 後 1–32 字；不只接受 S/M/L；輸出一定陣列 |
| Unit price | unit_price | 輸入數字或十進位字串；非負、有限、至多兩位有效小數（額外尾零可接受）；輸出固定兩位小數字串 |
| inventory | inventory | 嚴格 JSON 整數 0–2147483647；拒絕 true、字串數字、小數 |
| color | colors | 輸入字串陣列或分隔字串；正規化後 1–50 項，每項 trim 後 1–64 字；輸出一定陣列 |

不接受未知欄位、null、空集合、空白字串、非字串集合元素；trim 後重複集合值回 422。集合沒有輸入順序語義，回應按大小寫敏感字串升序固定排序。sizes/colors 複數表示集合，README 與 OpenAPI 必須明示題目映射。

### 尺寸／顏色字串相容規則

API 收到 JSON 後、進入商品交易前，統一正規化為字串陣列；DB 仍存關聯，不存拼接文字。兩欄可各自選不同輸入型態，POST/PUT/可選 PATCH 規則相同；這只是 body 相容，不把單值查詢篩選自動拆成多值。

1. 字串以三個明確分隔符 `、`（頓號）、`,`（半形逗號）、`，`（全形逗號）切分，允許混用；不是 CSV，不解析引號或跳脫，不以空白／分號拆分。
2. 字串原始長度上限 4096 字元（**先檢查再 trim**）；再逐項 trim 首尾空白，檢查 1–50 項和各項長度。單字串 `"Blue"` 是一項。
3. 重複分隔符、開頭／結尾分隔符造成空項時回 422，不靜默丟棄；trim 後重複值亦回 422。
4. 陣列元素是完整標籤，不再逐項拆分；`["Blue、Red"]` 回 422，避免混合格式猜測。尺寸／顏色標籤不得包含上述三分隔符；含逗號的標籤名不在本案支援範圍。
5. `"Blue Red"` 是一個標籤，不猜成兩色；`"Blue"` 與 `"blue"` 不自動合併。陣列同樣逐項 trim、限制長度和檢查重複；不修改客戶端原始陣列物件。
6. 回應一律是排序後的 JSON 陣列，不跟隨請求型態回字串；解析失敗不建立商品／屬性。

| colors 輸入 | 正規化／驗證結果 | 成功回應欄位 |
| --- | --- | --- |
| `["Blue", "Red"]` | 兩項 | `["Blue", "Red"]` |
| `"Blue、Red"` | 兩項 | `["Blue", "Red"]` |
| `" Red, Blue "` | trim 後兩項 | `["Blue", "Red"]` |
| `"Blue，Red"` | 兩項 | `["Blue", "Red"]` |
| `"Blue"` | 一項 | `["Blue"]` |
| `"Blue、、Red"` / `"Blue、"` / `"、Blue"` | 空項，422 | 不寫入 |
| `"Blue、 Blue"` / `["Blue", " Blue "]` | 重複值，422 | 不寫入 |
| `""` / `"  "` / `[]` / `null` / `123` / `["Blue", 123]` | 型態／空值不合法，422 | 不寫入 |
| `["Blue、Red"]` | 陣列元素含保留分隔符，422 | 不寫入 |

尺寸例 `"S、M"` 亦按相同規則處理，成功回應 `["M", "S"]`。4096 原始字元、50 項及個別標籤長度都須驗證，不能只套其中一種限制。

實作方向：request model 內部仍用 list[str]，以 Pydantic v2 before validator 做轉換並續做型別驗證；公開 input JSON Schema 顯示 string 或 array（anyOf），response model 只顯示 array。須實際檢查 `/openapi.json`，不能只在 Python 註解說支援字串。

POST 與 PUT 全部七欄必填。id 是伺服器給定唯讀欄位，不出現在寫入 body。

```json
{
  "name": "Star",
  "code": "A-001",
  "category": "cloth",
  "sizes": ["S", "M"],
  "unit_price": "200.00",
  "inventory": 20,
  "colors": ["Red", "Blue"]
}
```

成功商品回應：

```json
{
  "id": 1,
  "name": "Star",
  "code": "A-001",
  "category": "cloth",
  "sizes": ["M", "S"],
  "unit_price": "200.00",
  "inventory": 20,
  "colors": ["Blue", "Red"]
}
```

## 6. REST 端點與行為

全部位於 `/api/v1`；id 是 1–2147483647 的整數（對齊資料庫 INTEGER），超限回 422；所有有內容的回應 Content-Type application/json。

| 方法／路徑 | 行為 | 成功 | 失敗 |
| --- | --- | --- | --- |
| POST /products | 新增商品與屬性關聯 | 201，商品；Location 指向 /api/v1/products/{id} | code 重複 409；輸入不合法 422 |
| GET /products/{id} | 讀單筆 | 200，商品 | 查無 404；id 不合法 422 |
| GET /products | 列表，預設 id 升序 | 200，分頁物件 | 分頁不合法 422 |
| PUT /products/{id} | 全部替換七個可寫欄位，不存在不新增 | 200，商品 | 查無 404、衝突 409、缺欄位或不合法 422 |
| DELETE /products/{id} | 真正刪除商品與映射 | 204，無 body | 查無 404；id 不合法 422 |
| PATCH /products/{id}（可選） | 部分更新，集合欄位一旦提供即全部替換 | 200，商品 | 空 body/null/不合法 422、查無 404、衝突 409 |

列表參數：limit 預設 20，範圍 1–100；offset 預設 0，範圍 0–100000，避免無界限跳過。回應 `{"items": [...], "total": 4, "limit": 20, "offset": 0}`；total 是篩選後、分頁前商品數。空集合或 offset 超過末頁仍 200、items 空陣列。

可選查詢 `code`、`category`、`size`、`color`（每個參數最多一值），trim 後精確且大小寫敏感；多條件以 AND 結合。未知屬性篩選回空列表，不建立屬性。以 EXISTS 或去重查詢避免多對多 join 導致商品重複、total 錯誤與錯誤分頁。

422 的 detail 使用 FastAPI 標準驗證錯誤陣列；404/409/503 用 `{"detail": "固定簡短訊息"}`。409 message 為 `Product code already exists`；404 為 `Product not found`；DB 連線不可用回 503 `Database unavailable`。非預期程式錯誤回 500，不把 SQL、連線 URL、堆疊或密碼送給 API 使用者。先驗證 body，再找商品：錯誤 body 及不存在 id 同時出現時允許先 422。

PUT/PATCH 必須在同一交易更新商品和兩個映射集合；驗證失敗或 UNIQUE 衝突，不得部分更動。更新時先鎖定商品列，交易結束才釋放，確保兩個同時的替換不混出第三種集合。新屬性也隨該交易回滾。PATCH 未提供的欄位不變，不將缺省誤當 null。

DELETE 同一 id 第二次回 404；資料的最終狀態仍是不存在，符合刪除重複操作的資料語義。不承諾重複請求都回相同狀態碼。

## 8. 啟動契約（基本模式已實作；app 容器模式仍為設計）

命令以程式碼根為基準；POSIX shell 示例。README 須寫清楚 Python 3.12、Docker Compose v2、可用埠、設定值與故障排除。要求完整文件，不要求兩套原始碼。

基本模式的完整啟動、設定、測試與 curl 範例以 [README](../README.md) 為準；下列基本命令與實作一致。可選 app 容器模式未實作，不要把它當成目前可執行流程。

### 基本：本機 Python，DB Docker

```bash
python3 setup_env.py
# 第一次生成隨機密碼與兩個對齊的 URL；既有 .env 會拒絕覆寫，請保留

python -m pip install -r requirements-dev.txt
```

app 設定需載入 `.env`，不要求使用者 source 任意 shell 檔。資料庫健康等待須有有限 timeout 和失敗訊息。一般本機不支援時可使用可選全 Docker 流程，不改系統 Python。

### 加分：app 與 db Docker（尚未實作，以下僅設計契約）


### 驗證與停止

API 範例埠為 8123，互動文件 `http://127.0.0.1:8123/docs`，OpenAPI `/openapi.json`。埠衝突可選其他埠，不終止既有服務。

```bash
curl http://127.0.0.1:8123/api/v1/products
docker compose -p gainmiles-test --profile test up -d --wait --wait-timeout 120 db_test
# setup_env.py 已設定專用 TEST_DATABASE_URL；pytest 不得對應用資料庫做清空
pytest -q
docker compose -p gainmiles-test --profile test down
```

本機 API 以 Ctrl+C 停止；Compose down 保留 named volume。不把 down -v 當正常停止步驟。測試資料庫需專用、具名稱與 URL 護欄；若 TEST_DATABASE_URL 缺失或與 DATABASE_URL 相同，測試停止，不清空商品資料。獨立測試 PostgreSQL 的完整建置命令須在 README 補齊。
